# Training upload implementation and verification

Deployed 2026-09-05 to the authorized server. Health: https://myneri.top/api/training/health. Photos and paired JSON are sent from the desktop directly to Microsoft; this endpoint only authorizes, verifies and manages submissions. The destination is OneDrive `NeriCloud/Neri_Data/Training`, grouped by species, with confirmed empty photos under `空照片`.

Server code: `/opt/neri-training/training_broker`. Unit: `neri-training.service`, dedicated user, loopback port 8001, one worker. Private state: `/var/lib/neri-training`. Protected environment: `/etc/neri-training.env`. No credentials are included in this repository. nginx, the existing website API and OpenList remained active after deployment. Deployment backup: `/var/backups/neri-training-20260905-132149`.

OpenList ACL was restricted on the Training directory with inheritance; no existing descendant override was present. A temporary ordinary account could list `/` (200) but received 403 for Training and a descendant; administrator access returned 200. The temporary account was removed afterward.

The live test generated a synthetic 320×200 JPEG with metadata, prepared a stripped 675-byte JPEG and 519-byte JSON, then uploaded from the local machine to the returned Microsoft session URLs. Pair verification, repeated completion receipt, changing species to a new revision and owned deletion all succeeded. A final refreshed remote check found zero test revisions and empty test directories; those two empty directories were removed. No user photo/video was used.

The implemented Windows workflow shows the agreement before normal use, requires an explicit separate participation choice, permits refusal without disabling core features, and provides settings to stop participation or clear waiting tasks. Upload preparation/network run in the background after successful manual annotation saves. Each physical folder contributes at most three confirmed empty photos, including after renaming/restarting/multiple app instances; manually confirmed species photos are not subject to that empty-photo limit.

Python verification: 38 tests passed across training queue/media, local privacy API/integration, broker ownership/cleanup/quota, transport and existing empty-photo deletion. Operational limits: metadata removal does not remove identities visible in pixels.
