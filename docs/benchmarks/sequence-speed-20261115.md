# 序列汇总速度对比（2026-11-15）

这是同一台机器上的合成数据基准，不是完整照片任务的耗时。CUDA 部分仅为独立原型，未接入生产汇总流程。

- 优化前：Git 提交 `ced18f357f7eaa384d54b9f2cfba427e739977fb` 的源码。
- 优化后：当前工作区源码；JSON 记录了被测文件 SHA-256。
- Python 3.13.11；NumPy 2.5.3；SQLite 3.50.4；OpenBLAS 限制为 4 线程。
- GPU：NVIDIA GeForce RTX 5070 Ti；PyTorch 2.14.0+cu132；TF32=False。
- 每项运行 3 轮，交替执行新旧实现，以下为中位数。计时不包含数据生成、垃圾回收和输出校验。
- 历史筛选包含索引构建；任务库和目录库在已有初始结果上计时更新。
- SQLite 位于工作区 E: 盘的独立临时目录，未访问或修改用户任务数据库。
- 图像为生成的 PNG，文件受操作系统缓存影响，不能外推冷盘、大 JPEG 或网络盘表现。

## 已落地的 CPU 优化

| 阶段 | 优化前（秒） | 优化后（秒） | 前/后耗时比 |
|---|---:|---:|---:|
| 历史索引与筛选：1,000 框 | 0.160277 | 0.016010 | 10.01× |
| 历史索引与筛选：4,000 框 | 1.998501 | 0.137000 | 14.59× |
| 事件与轨迹分组：100 帧、每帧 3 框 | 1.846950 | 0.003032 | 609.15× |
| 历史特征整合：4,000 框、64 条历史、768 维 | 0.676221 | 0.326774 | 2.07× |
| 任务库：4,000 张照片、全部结果变化 | 0.284715 | 0.140851 | 2.02× |
| 任务库：4,000 张照片、1% 内容变化，全部对象替换 | 0.314715 | 0.082326 | 3.82× |
| 目录数据库：4,096 张照片、16 个目录 | 1.722539 | 1.908300 | 0.90× |
| 解码与指纹合计：64 张 512×512 PNG | 0.044200 | 0.022664 | 1.95× |

目录数据库单次连接数从 384 降为 128，但本轮没有稳定速度收益。三轮旧实现分别为 2.232s, 1.704s, 1.723s；新实现分别为 2.175s, 1.411s, 1.908s。

CPU 新旧结果均通过校验：历史索引、轨迹、解码像素、指纹和数据库逻辑内容一致；历史整合使用 rtol=1e-6、atol=1e-7 数值容差。

## 独立 CUDA 历史整合原型

这里的基线是已经优化过的 CPU 实现；CUDA 时间包括特征和索引上传、计算、结果下载，排除首次初始化。CPU 分块 128，CUDA 分块 512；均为 FP32。

| 数据量 | 当前 CPU（秒） | CUDA 原型（秒） | 前/后耗时比 | 最大绝对误差 |
|---|---:|---:|---:|---:|
| CUDA 原型：1,000 框历史特征整合 | 0.083713 | 0.003124 | 26.80× | 2.24e-08 |
| CUDA 原型：10,000 框历史特征整合 | 0.624078 | 0.033985 | 18.36× | 2.98e-08 |

该原型尚未验证真实模型的分类、轨迹和拒识门限一致性；上述倍数不能作为完整序列汇总或全任务提速倍数。
