# Neri1.1 批处理恢复与序列汇总进度

DINOv3 照片推理每批完成后，会将检测结果、检测框元数据和原始精度的
crop embedding 一起提交到本地 SQLite 缓存。缓存位于任务状态文件旁的
`dinov3_features/` 目录，以任务 ID 的 SHA-256 命名；成功检测但没有目标的
照片也有完成记录。

继续任务时，先恢复缓存中的结果和 crop collector，只推理没有有效缓存的照片，
然后按原始文件顺序重新进行完整序列汇总。关闭或重启后端后同样可以恢复。
序列汇总内部的分类和聚类会重新计算，不从其内部中断点继续。

缓存校验包括原始文件大小及修改时间、模型清单（含编码器与分类检查点指纹）、
探测模型路径及大小/修改时间、处理参数和检测框/特征完整性。变化或损坏的
照片缓存会失效；模型或参数变化会使整个任务的特征缓存失效。
正常完成或删除任务后清理缓存，停止或失败时保留。

旧版本已经停止的任务没有这些特征缓存，升级后首次继续仍须重新推理。
首次重新推理过程中生成的缓存可供后续继续任务使用。

任务 API 增加以下字段，前端沿用任务轮询同步显示：

- `sequence_stage`：当前汇总阶段；非汇总阶段为 `null`。
- `sequence_processed`、`sequence_total`：当前阶段的完成数量与总数量。

界面保留照片处理数量，汇总进度条则显示当前阶段的进度，例如照片指纹计算、
因果历史构建、历史特征整合与结果写入。全序列分类、事件分组和拒识聚类
没有可靠的内部完成比例，显示阶段名称与活动进度条，不推算百分比或剩余时间。
Windows 任务栏进度和托盘提示同步采用上述阶段信息。
