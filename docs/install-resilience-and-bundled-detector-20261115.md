# Neri1.2preview 安装恢复与内置 LiteRT 保护

2026-11-15。

## 两个问题的实际原因

11 月 14 日 23:17:16 至 23:21:56 的另一台电脑安装记录，只能确认凭证接口 `/dinov3/direct` 请求失败，无法从旧日志还原 HTTP 状态或底层网络错误。旧客户端没有为该请求重试；分段中的凭证刷新位于重试区外，失败会结束安装并清除 staging。不能据此确定发生过 HTTP 429。

LiteRT 探测器实际上已在 nightly `be2aee69` 的包中：CI 组装及 artifact 下载后都验证了 `model/detect/sync/MDV6-yolov10-c.tflite`，大小 4,717,072 字节，SHA-256 为 `d66f8fc9ca1f2c1b7c7ec322d4af67964e0ecf24d5a5e2f05ae6f8b76c7d23ef`。排查时线上普通模型清单没有该文件，而启动同步会删除 sync 目录中不在清单内的文件，因此内置探测器可能在成功同步后消失。

## 安装器修复

- 清单和凭证 JSON 请求对临时网络错误及 HTTP 408/425/429/500/502/503/504 最多尝试 5 次，逐步等待。支持合理的 Retry-After；过长等待要求会退出并保留缓存。401/403/404/409/422 等不盲目重试。
- Windows 上，元数据请求与文件分段都可在 Python TLS 失败后使用系统 curl。继续校验证书，不使用 insecure 选项；原生请求保留 HTTP 状态和重试提示。
- 凭证刷新纳入分段异常处理，凭证请求自己的重试预算耗尽后不再套用另一层 5 次循环，避免放大成 25 次请求。
- 本地维护日志记录文件、阶段、尝试次数、耗时、HTTP 状态、允许的服务端错误码、底层异常链和脱敏堆栈。下载令牌、代理路径令牌、签名 URL 与授权字段不写入日志。
- 失败状态保留最后实际进度，不再固定显示 100。

## 可恢复缓存与原子安装

缓存目录为 `res/model/.dinov3-download-cache/<manifest_id>/`，与激活中的组件和临时 staging 分开。完整文件复用前检查大小和 SHA-256；部分文件的元数据绑定大小、目标哈希、分段大小、已提交偏移和前缀哈希。恢复时重算前缀哈希，损坏或不匹配的缓存重新下载，崩溃后未提交的尾部会截断。

每个分段只在完整收到并验证 Range 后写入，落盘后原子提交缓存元数据。全部资产完成后仍须通过整文件哈希和组件健康检查，才能原子替换现有组件。失败只删除 staging，已验证缓存保留，现有组件不被覆盖。旧多原型文件仍按原契约报告不兼容，不伪装成新版组件。学习数据库使用原有 state 目录，此次没有迁移或清除。

## 内置探测模型修复

- 将 MDV6-yolov10-c.tflite、标签、许可证及来源说明移到 `res/model/detect/bundled/`，其字节和权重哈希不变。
- 模型目录增加 bundled 来源；开始页与设置页显示“内置模型”。云同步继续只管理 sync 目录，无法删除或覆盖内置模型。
- 兼容旧安装保存的 MDV6 sync 路径，将其解析到新的内置位置。
- 打包和 artifact 下载后的校验必须找到这个指定探测器；仅有其他 LiteRT 文件也不能让构建通过。
- 下载后的实际安装包还会发现内置模型并执行一次 CPU 推理，检查输出有效。
