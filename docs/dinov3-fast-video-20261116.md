# DINOv3 快速视频识别

选择 DINOv3 分类模型（PyTorch CPU/GPU 或 LiteRT CPU）后，可以使用「快速识别」处理视频。旧安装包无需重导出模型；模型列表按当前程序支持情况启用快速视频模式。完整视频追踪仍不支持。

快速模式沿用现有设置：`vid_stride` 表示每段视频均匀抽取的帧数，`batch_size=0` 使用自动批量策略，内存不足时自动减小批量重试。CPU 自动策略保留较小的内存占用；显式设置批量大小可按机器资源调整。

解码和预处理与推理重叠执行，采样帧直接通过内存传递，不生成临时 JPEG。每个目标裁图只编码一次，等同一视频的全部采样帧齐备后统一分类；同帧不同目标分别关联轨迹，不把另一段视频当作历史上下文。保持现有 FP32 编码、裁图和拒识协议，拒识框保留为 Unknown。视频完成判定后才保存结果和发布完成进度；中断后可复用已完成的视频，未完成的视频重新采样。

## 本机测量

2026-11-16，PyTorch 2.14.0+cu132、8 个 CPU 推理线程、NVIDIA GeForce RTX 5070 Ti。探测模型为 MDV6-yolov10-c，分类模型为本地 DINOv3 `experiment_full`，均使用 FP32，探测输入 640、关闭增强、置信度阈值 0.1。

测试输入由本地一张野生动物照片生成：20 秒、640×480、25 FPS MJPEG 视频，画面横向移动 0–4 像素，均匀抽取 12 帧，最终得到 24 个目标框。测量包括采样、预处理、探测、DINOv3 编码、完整采样序列分类和结果入库；不含模型加载。每种配置先预热一次，再测三次，取中位数。

| 设备 | 批量大小 | 单段视频处理耗时 |
| --- | ---: | ---: |
| CPU | 1 | 2.021 秒 |
| CPU | 4 | 1.823 秒 |
| RTX 5070 Ti | 1 | 0.446 秒 |
| RTX 5070 Ti | 4 | 0.377 秒 |

这些数字是当前机器上单个构造样本的测量，并非旧版本对比、准确率评估或所有视频的速度保证。真实视频的编码、分辨率、采样数量、目标数量和机器负载都会影响耗时。LiteRT CPU 路径有独立功能测试；本表只测量 PyTorch CPU/GPU。

原始测量数据位于本地 `runs/dinov3-fast-video-20261116/benchmark.json`，复现脚本位于 `temp/benchmark_dinov3_fast_video_20261116.py`，均不随 Git 提交。

## 验证记录

- 24 个相关 Python 测试文件：299 项通过，1 项跳过（没有对应的本地 LiteRT 编码器实物资产，跳过实物单裁图 smoke test）。覆盖视频流水线、任务续跑、模型能力、照片序列、LiteRT 合约、批量重试和结果存储。
- Flutter 模型选择和视频设置测试：31 项通过。测试环境输出了 media_kit 原生播放依赖提示；此处验证的是设置和请求行为，视频解码/推理另由 Python 集成测试与上述实测覆盖。
