# Neri1.2preview CPU / GPU 共享学习

同源的 Neri1.2preview LiteRT FP32 与 PyTorch 版本共用补图、新增物种、校准和撤销记录。在“设置 → 环境维护”的 Neri1.2preview 组件中可选择“自动检测”、“CPU（LiteRT FP32）”或“GPU（PyTorch）”，通过 NeriCloud 安装或切换组件。默认使用自动检测，有支持的 GPU 时选择 GPU 版本，否则选择 CPU 版本。CPU 版本无需 PyTorch，GPU 版本按需补齐运行环境。已安装的运行版本和选择说明可在“设置 → 调试模式 → 联合模型运行环境”中查看。

## 模型身份与持久化

共享身份由原始编码器 SHA-256、冻结基础分类头 SHA-256、架构、预处理和推理配方共同计算，不使用显示名或安装路径。当前自动识别已验证的 Neri1.2preview FP32 / PyTorch 配对。Neri1.1、不同基础版本和未经批准的转换保持独立。

学习记录继续存放在用户状态目录的 `dinov3_learning.sqlite3`，以稳定的 family ID 为键。最新分类头、完整校准包和冻结基础模型存放在 `learning-families/<ID>/model.neri.json` 及相邻资产目录。Windows 默认状态根目录是 `%LOCALAPPDATA%/Neri`；显式设置 `NERI_DINO_STATE_DIR` 时使用该目录。

两个运行方式读取同一份最新分类头，切换时只选择编码器。编码器权重按校验和缓存，支持同卷硬链接或跨卷复制，GPU 源码随对应权重保存。首次迁移后更换安装目录、删除旧安装资源不会清除共享档案。CPU 和 GPU 仍有独立的推理缓存指纹，避免误用旧识别缓存。

## 已有学习成果迁移

首次加载会检查当前安装中的同源模型，也会通过旧 SQLite 记录查找其他安装目录的模型。迁移同时保留分类头、基础模型、校准、样本特征和撤销链。原模型文件和旧路径下的数据库记录不删除，迁移回执使重试幂等，已撤销样本不会在重新选择另一后端时复活。

升级时先退出旧版并保留原安装目录，等待首次加载完成迁移。旧目录仍可读取时可核对基础模型与校准身份；迁移完成后共享档案即可独立使用。若两版对同一检测框有不同校验、校准包不同，或旧模型缺失必要学习记录，会停止自动合并并保留原数据，不会猜测覆盖。

共享档案保留已提交样本的独立快照。清除待学习修正会恢复已发布的支持和原撤销链；已学样本的特征可跨已验证后端使用，因此原照片移走后仍能撤销或改标签。未提取特征的新补图仍需要原照片。

## 并发与恢复

CPU/GPU 选择或状态轮询不使有效的学习计算反复作废。发布时检查共同分类头和校准版本，并合并新登记的编码器信息；人工校验发生变化时重新合并学习。迁移中断可重试，SQLite 旧记录保留，模型清单按原子替换发布。重启后继续处理待学习样本；若 PyTorch 不可用且已登记 CPU 编码器，可使用 CPU 恢复。
