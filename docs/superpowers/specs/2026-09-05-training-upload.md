# Neri consent and training uploads

Approved user request: first-use agreement; separately opt in to background photo compression and annotation uploads while marking. Camera-trap photos are grouped into trigger events by capture time: adjacent timestamped photos no more than 10 seconds apart belong to one transitive event, and at most one validated photo from that event is contributed. Photos without a readable capture timestamp are not merged with other photos. Each physical source folder still contributes at most three confirmed empty-photo samples, persisted across restarts. Confirmed species photos are uploaded and categorized by every assigned species. Destination is OneDrive/NeriCloud/Neri_Data/Training (OpenList /Neri_Data/Training).

Operator: 和錦わきん. Privacy contact: wakin721@outlook.com. Agreement version: 2026-09-05. The supplied draft is source material, updated for explicit automatic submission and Microsoft global storage. Do not promise irreversible anonymity: strip metadata/paths and exclude known person/vehicle labels; visual identities/watermarks require user screening. Photos only, no video or library scans. Nothing uploads before explicit separate opt-in; declining has no effect on core functions. Withdrawal cancels pending/in-flight work before the next transfer; completed submissions are not silently deleted.

Architecture: Flutter consent/settings UI calls the local Python privacy API. A dedicated SQLite journal under the user's local application data keeps consent, per-source identities, trigger-event identities, reservations and retry state (outside disposable temp/cache). Annotation persistence only enqueues lightweight work. One daemon worker debounces for ten seconds, compresses JPEG to max long edge 2048 / quality 82, strips metadata, creates per-species YOLO text labels, and uses a cloud broker for short-lived OneDrive upload sessions. Do not alter local source images. Compressed bounding boxes must stay consistent with stored pixel orientation; ambiguous EXIF-rotated model boxes are omitted rather than transformed speculatively.

Species naming: remote folders remain the Chinese verified species names. The YOLO class metadata uses `res/species_database.db`: lookup `species.中文名 -> species.学名`, normalize whitespace to underscores (for example `棕脸鹟莺 -> Abroscopus_albogularis`), and fall back to lowercase underscore-separated Hanyu Pinyin when no scientific name is available. Confirmed empty samples use class name `background`.

Local API: GET /api/privacy -> {agreement_version, agreement_accepted, participation_decided, training_enabled, stats:{pending,uploading,uploaded,failed,skipped}}. PUT /api/privacy body {agreement_version:'2026-09-05',training_enabled:bool} persists acceptance and explicit choice. DELETE /api/privacy/queue discards waiting jobs while retaining completed empty-photo quota/history. Both mutations return the status object. Generic settings cannot set consent.

Cloud base: https://myneri.top/api/training. POST /v1/submissions body includes {sample_id:32 hex, revision:positive int, secret:per-sample random token, species:list of Chinese labels, image_bytes:int, annotation_bytes:{species:int}, classes_bytes:{species:int}}. Empty category is 空照片. Response targets use kinds `image`, `annotation`, and `classes`. Completed retries return already_complete:true and targets:[]; clients validate sample ID/revision before accepting that receipt. POST /v1/submissions/{sample_id}/complete body {revision,secret} verifies all files and their sizes, then replaces older revisions/categories. DELETE /v1/submissions/{sample_id} body {secret} deletes only that owned submission. DELETE on a cancellation capability removes the incomplete attempt and any finished partial files. Broker uses a server-owned fixed destination, validates labels/lengths and declared sizes, and persists ownership/idempotency. No master credential reaches the desktop. Upload URLs are bearer capabilities; never log them. No authorization header on OneDrive PUTs.

Remote storage: each Chinese species directory receives three files for the representative sample: `Training/{中文物种}/{sample}-r{revision}-{attempt}.jpg`, matching YOLO `{sample}-r{revision}-{attempt}.txt`, and `{sample}-r{revision}-{attempt}.classes.txt`. The YOLO label uses standard `class_id x_center y_center width height` normalized coordinates; because each species directory is treated as a single-class contribution, matching boxes use class id 0 and `.classes.txt` contains the resolved scientific-name/pinyin class. Empty samples use an empty label file. Path-unsafe labels and case-folding/Unicode-normalization collisions within one sample are rejected. Each attempt gets new recorded paths to avoid OpenList automatic rename-on-conflict. Subsequent label changes use a new revision; previous files are removed only once new files are complete. Pending updates coalesce. Undo to unverified removes pending work and queues removal of prior uploaded data.

User clarification: videos are excluded; photos and YOLO files travel directly from the desktop to OneDrive because server bandwidth is limited. The server handles only small control requests. The public API has no photo relay route. OpenList session file_size is not an enforced Microsoft ceiling: daily byte budgets limit declared sizes; completion checks actual sizes and removes mismatches. Incomplete attempts are revoked and removed after 20 minutes, on five-minute sweeps; completed revisions expire after 365 days. Failed cleanup stays journaled and retries. An interprocess OS lock protects broker operations across explicit commits; the desktop uses physical file/directory IDs, trigger-event IDs, atomic SQLite reservations and a separate interprocess worker lock.
